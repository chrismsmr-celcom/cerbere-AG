# Self-hosting Cerbere AG

Run the Cerbere AG collector and dashboard on your own infrastructure. Your
agents' prompts, tool calls and decisions stay in your PostgreSQL database.

## What you need

- Docker 24+ with the Compose plugin
- 2 vCPU / 2 GB RAM for the default (regex + rules) setup; more if you enable the local ML model
- A DNS name and a reverse proxy providing HTTPS for anything beyond a local evaluation

## Quick start (about 5 minutes)

```bash
git clone https://github.com/chrismsmr-celcom/cerbere-AG.git
cd cerbere-AG

./scripts/selfhost-init.sh            # writes .env with random secrets
docker compose up -d --build          # collector + PostgreSQL + Redis
docker compose exec collector python -m collector.cli create-admin --email you@company.com
```

Then open `http://localhost:8080/login` and sign in with the email and password you
just chose. The password is requested interactively (12 characters minimum) and
stored hashed (scrypt). No email server and no external identity provider are needed.
You can add company SSO afterwards (see [Single sign-on](#single-sign-on-oidc)).

Check health: `curl http://localhost:8080/healthz`.

## Point your agents at your instance

```python
from agentguard import AgentGuard

guard = AgentGuard(
    collector_url="http://localhost:8080",   # your AGENTGUARD_PUBLIC_URL
    api_key="ag-...",                         # create keys in the dashboard
    agent_id="my-agent",
)
```

The `/documentation` page and DevTools use `AGENTGUARD_PUBLIC_URL` in their
examples, so they show your instance and not the hosted cloud.

## Configuration

All settings are environment variables in `.env`. The essentials:

| Variable | Purpose |
|---|---|
| `POSTGRES_PASSWORD`, `AGENTGUARD_API_KEY`, `AGENTGUARD_ADMIN_SECRET`, `AGENTGUARD_FLASK_SECRET` | Required secrets (generated by `selfhost-init.sh`). Compose refuses to start without them. |
| `AGENTGUARD_PUBLIC_URL` | URL your users and agents use to reach Cerbere. |
| `AGENTGUARD_CORS_ORIGINS` | Origins allowed to call the API from a browser. Required in production mode. |
| `AGENTGUARD_COOKIE_SECURE` | Set `true` once you serve over HTTPS. Default `false` so a plain-HTTP evaluation works. |
| `AGENTGUARD_TRUSTED_PROXIES` | Number of reverse proxies in front of Cerbere (usually `1`). Without it, rate limits see the proxy's IP for every client. |
| `AGENTGUARD_SIGNUP_ENABLED` | Public `/signup`. Keep `false`: it creates an admin workspace for any visitor. |
| `AGENTGUARD_PASSWORD_LOGIN_ENABLED` | Password sign-in. Default `true`. |
| `AGENTGUARD_MAGIC_LINK_ENABLED` | Email sign-in links. Default `false` in Compose; needs `AGENTGUARD_SMTP_HOST`. |
| `AGENTGUARD_OIDC_*` | Company SSO. See [Single sign-on](#single-sign-on-oidc). |
| `AGENTGUARD_USE_LLM_JUDGE`, `AGENTGUARD_JUDGE_URL`, `AGENTGUARD_JUDGE_MODEL`, `AGENTGUARD_JUDGE_API_KEY` | Optional LLM judge. Any OpenAI-compatible endpoint works. |
| `AGENTGUARD_ENVIRONMENT` | `production` by default in Compose (strict startup checks). |

See `env.example` for the full list.

## Keeping data on-site

Cerbere makes no outbound calls by default. Data only leaves your network if you configure it to:

- **LLM judge:** with `AGENTGUARD_USE_LLM_JUDGE=true`, flagged content is sent to `AGENTGUARD_JUDGE_URL`. The default value points to a hosted API; for a fully on-site setup, point it to your own server (Ollama, vLLM, a private Azure/OpenAI deployment).
- **Alerts:** Slack/webhook/email alerts go to the endpoints you set.
- **OpenTelemetry:** only if `OTEL_EXPORTER_OTLP_ENDPOINT` is set.

## HTTPS with a reverse proxy

Put Caddy, nginx or Traefik in front of Cerbere. Example with Caddy on the host:

```
cerbere.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Then in `.env`:

```
AGENTGUARD_PUBLIC_URL=https://cerbere.example.com
AGENTGUARD_CORS_ORIGINS=https://cerbere.example.com
AGENTGUARD_COOKIE_SECURE=true
AGENTGUARD_TRUSTED_PROXIES=1
```

To stop exposing port 8080 on every interface, change the `ports` entry of the
`collector` service to `"127.0.0.1:8080:8080"`.

## Encrypting the database connection (optional)

The collector reaches PostgreSQL over the private Docker network. To also
encrypt that link, add the TLS overlay to every `docker compose` command:

```bash
docker compose -f docker-compose.yml -f docker-compose.tls.yml up -d --build
```

On first start a certificate specific to your installation is generated into
the `agentguard_certs` volume and the collector connects with `verify-full`.
To use your own PKI, replace `server.crt`, `server.key` and `ca.crt` in that volume.

## Single sign-on (OIDC)

Let your people sign in with your identity provider (Okta, Microsoft Entra ID,
Google Workspace, Keycloak, Auth0, Authentik, ...). It is built into Cerbere and
does not depend on any external service.

**1. Register Cerbere in your identity provider** as a *web application* using the
authorization code flow, with this redirect URI:

```
<AGENTGUARD_PUBLIC_URL>/auth/sso/callback
```

**2. Create the first administrator** with `create-admin` (SSO users join this
organization; they do not get a workspace of their own).

**3. Configure `.env`, then `docker compose up -d`:**

```
AGENTGUARD_OIDC_ISSUER=https://acme.okta.com
AGENTGUARD_OIDC_CLIENT_ID=...
AGENTGUARD_OIDC_CLIENT_SECRET=...
AGENTGUARD_OIDC_ALLOWED_DOMAINS=acme.com
AGENTGUARD_OIDC_GROUP_ROLE_MAP=cerbere-admins=admin,cerbere-devs=developer,cerbere-auditors=auditor
AGENTGUARD_OIDC_BUTTON_LABEL=Okta
```

A "Sign in with Okta" button appears on `/login`.

| Variable | Meaning |
|---|---|
| `AGENTGUARD_OIDC_ISSUER` | Issuer URL of your provider (must be `https://`). |
| `AGENTGUARD_OIDC_ALLOWED_DOMAINS` | **Required.** Comma-separated email domains allowed to sign in, or `*` to accept any email your provider verifies. Without it SSO stays disabled. |
| `AGENTGUARD_OIDC_DEFAULT_ROLE` | Role for people with no mapped group (`viewer` by default). |
| `AGENTGUARD_OIDC_GROUP_ROLE_MAP` | `group=role` pairs. When set, your provider is the source of truth: the role is recomputed at every sign-in (highest role wins). |
| `AGENTGUARD_OIDC_GROUPS_CLAIM` | Claim holding the groups (default `groups`). |
| `AGENTGUARD_OIDC_REQUIRE_EMAIL_VERIFIED` | Default `true`. See the Entra note. |
| `AGENTGUARD_OIDC_ORG_ID` | Target organization. Only needed if the instance has several (see `list-users`). |

**Provider notes**

- **Okta:** issuer is your Okta URL (or a custom authorization server). Add a `groups` claim to the ID token.
- **Microsoft Entra ID:** issuer is `https://login.microsoftonline.com/<tenant-id>/v2.0`. Entra does not send `email_verified`, so set `AGENTGUARD_OIDC_REQUIRE_EMAIL_VERIFIED=false` (safe for a single-tenant app registration, where your tenant controls the addresses). Group claims contain group object IDs, so use those IDs in the role map.
- **Google Workspace:** issuer is `https://accounts.google.com`. Set `AGENTGUARD_OIDC_ALLOWED_DOMAINS` to your own domain(s): anyone with a Google account can reach the provider.
- **Keycloak:** issuer is `https://<host>/realms/<realm>`. Add a group-membership mapper that emits `groups`.

**How accounts are matched.** People are identified by the provider's stable user ID,
not by email. An existing account (for example the first administrator) is linked on
first SSO sign-in only if your provider reports the email as verified and the account
is in the same organization; an account already linked to a different identity is never taken over.

**Requiring SSO.** Once SSO works for everyone, hide the other methods with
`AGENTGUARD_PASSWORD_LOGIN_ENABLED=false` (and `AGENTGUARD_MAGIC_LINK_ENABLED=false`).
Test SSO before doing this. If your provider is ever unavailable, set the variable back to `true` and restart to regain access with the administrator's password.

**Not included yet:** SAML (put Keycloak or Dex in front of Cerbere to bridge SAML to OIDC), several providers per instance, automatic user provisioning and deprovisioning (SCIM), and single logout.
A user removed in your provider keeps access until their Cerbere session expires or you disable the account.

## Users

```bash
docker compose exec collector python -m collector.cli list-users
docker compose exec collector python -m collector.cli create-admin --email other@company.com --role auditor
docker compose exec collector python -m collector.cli set-password --email you@company.com
```

Roles: `admin`, `developer`, `auditor`, `viewer`.

## Backup and restore

```bash
# backup
docker compose exec -T postgres pg_dump -U agentguard agentguard | gzip > cerbere-$(date +%F).sql.gz

# restore into an empty database
gunzip -c cerbere-2026-01-01.sql.gz | docker compose exec -T postgres psql -U agentguard agentguard
```

Also keep a copy of your `.env`: `AGENTGUARD_FLASK_SECRET` and any evidence-encryption key are needed to read existing sessions and sealed data.

## Upgrading

```bash
git pull
docker compose up -d --build
```

Schema changes are applied automatically at startup. Take a backup first.

## Production checklist

- [ ] Served over HTTPS; `AGENTGUARD_COOKIE_SECURE=true`
- [ ] `AGENTGUARD_TRUSTED_PROXIES` matches your proxy chain
- [ ] `AGENTGUARD_SIGNUP_ENABLED=false`
- [ ] `.env` is private (mode 600) and backed up outside the server
- [ ] PostgreSQL and Redis ports are not published (they are not, by default)
- [ ] Regular `pg_dump` backups, with a restore test
- [ ] LLM judge endpoint is one you control, or the judge is disabled

## Troubleshooting

- **`required variable POSTGRES_PASSWORD is missing`**: run `./scripts/selfhost-init.sh` first.
- **Signed in but immediately logged out over HTTP**: `AGENTGUARD_COOKIE_SECURE` is `true` without HTTPS.
- **`429 Too Many Requests` for everyone behind a proxy**: set `AGENTGUARD_TRUSTED_PROXIES=1`.
- **SSO: "Sign-in was refused"**: the page is deliberately vague. The exact reason is in the logs (`docker compose logs collector | grep sso_login_rejected`): domain not allowed, email not verified, no organization yet, several organizations, and so on.
- **SSO: redirect URI mismatch at the provider**: the registered URI must equal `<AGENTGUARD_PUBLIC_URL>/auth/sso/callback` exactly.
- **Logs**: `docker compose logs -f collector`
